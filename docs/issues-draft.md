# Draft issues: good first issues

Ten starter issues taken from the open TODOs in the development log. Each is small, has a clear finish line, and stays away from the security core (`AirGapGuard`, `net.rs`, key handling). A maintainer copies each into a GitHub issue with the labels shown, then deletes this file once all ten are filed.

Every issue links [CONTRIBUTING.md](../CONTRIBUTING.md) and the absolute rules in [CLAUDE.md](../CLAUDE.md).

---

## 1. rag: L2-normalize `doc_vector`

Labels: `good first issue`, `enhancement`

`VectorStore::doc_vector` in `src-tauri/src/rag/vector_store.rs` returns the plain mean of a document's chunk embeddings. Chunk embeddings are L2-normalized, but their mean is not, so cosine scores against it are off scale.

- Normalize the mean to unit length before returning it. Leave a zero vector unchanged.
- Add a unit test that checks the returned vector has norm 1 (within 1e-5).

Done when `cargo test` passes and the existing `doc_vector_ranks_its_own_doc_first` test still passes.

## 2. ipc: get and set exclude patterns

Labels: `good first issue`, `enhancement`

The scanner already reads gitignore-style exclude lines from the `exclude_patterns` setting (`ingest::scanner::EXCLUDES_SETTING`), but nothing can write it.

- Add `get_exclude_patterns() -> Vec<String>` and `set_exclude_patterns(patterns: Vec<String>)` in `commands.rs`, following the existing order (service call, then `AppError` conversion).
- Reject a line that does not parse as a gitignore pattern with a new `ErrorCode`.
- Types are generated by ts-rs. Do not write them by hand in `src/ipc/`.

Done when unit tests cover a valid list, an invalid line, and an empty list.

## 3. frontend: folder list

Labels: `good first issue`, `enhancement`

Show the registered folders using the `list_folders` IPC, which returns `FolderInfo` (status, document count, failed count).

- A small component in `src/components/` that lists each folder with its status and counts.
- Unavailable folders are visibly marked.
- No file paths in console logs.

Done when `pnpm lint && pnpm typecheck && pnpm test` pass and the component has a vitest test with a mocked IPC call.

## 4. frontend: add and remove folder buttons

Labels: `good first issue`, `enhancement`

Depends on #3. `add_watched_folder` opens the native picker from Rust and takes no path. `remove_watched_folder(id)` stops the watch and deletes the folder's documents.

- An "Add folder" button that calls `add_watched_folder` and shows `FolderWarning::BroadPath` when it comes back.
- A remove action per folder, with a confirmation that says its documents will be removed from the index (files on disk are untouched).
- Show `folder_overlap` and `folder_unreadable` errors as readable messages.

Done when vitest covers the warning and both error codes.

## 5. frontend: indexing progress indicator

Labels: `good first issue`, `enhancement`

The index queue emits `index://progress` (`IndexProgress`) at most every 250 ms, and `get_index_status` returns the current `IndexStatus`.

- Read `get_index_status` on mount, then listen to `index://progress`.
- Show the `done`, `queued`, and `failed` counts and the `paused` state. Hide it when nothing is queued or running.
- Unsubscribe on unmount.

Done when vitest covers the initial status, an update, and unmount.

## 6. rag: query-operator parser

Labels: `good first issue`, `enhancement`

Turn operators in a search box string into a `SearchFilter` (`src-tauri/src/rag/vector_store.rs`) plus the remaining query text.

- Support `ext:pdf`, `kind:text|pdf|docx|image` (`KindFilter`), `after:YYYY-MM-DD`, and `before:YYYY-MM-DD`.
- Unknown operators and malformed values stay in the query text unchanged.
- A pure function with no I/O, for example `parse_query(input: &str) -> (String, SearchFilter)`.

Done when table-driven unit tests cover each operator, repeats, malformed dates, and plain text.

## 7. eval: grow the retrieval eval set past 30 queries

Labels: `good first issue`, `help wanted`

`eval/queries.jsonl` has 30 queries, so one query moves Recall@5 by 0.04. Add 20 more against the existing public corpus in `eval/corpus/`.

- Spread them over the five kinds (`proper_noun`, `clause`, `numeric`, `concept`, `no_answer`).
- Each `relevant` anchor is an exact phrase from the corpus file. See `eval/README.md` for the format.
- Post the before and after numbers from `cargo run --example eval` in the PR.

Done when the eval runs and every new anchor is found in its file.

## 8. test: cover the unavailable-folder reconcile branch in the watcher

Labels: `good first issue`

The watcher has a branch where an event inside an unavailable folder reconciles that folder. No test reaches it today, because a root event always arrives first (see `src-tauri/src/ingest/watcher.rs`).

- Write a unit test that drives that branch directly, without a real file-system event if needed.
- Confirm the test fails when the branch is removed, and say so in the PR.

Done when `cargo test` passes with the new test.

## 9. bench: measure indexing speed on an M1 or M2 Mac

Labels: `help wanted`, `good first issue`

Indexing speed has only been measured on an M4. The decision to try ONNX Runtime depends on M1 numbers.

- Fetch the models (`bash scripts/fetch-models.sh`) and index the public eval corpus with a release build.
- Report the chip, macOS version, files per minute, and chunks per second, with the command you ran.
- Use only the public corpus in `eval/corpus/`. Do not benchmark or describe your own documents.

Done when the numbers are posted in the issue. No code change is needed.
